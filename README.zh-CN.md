## 为什么做这个

所有新闻软件都按**标签**来做个性化：你勾「科技」「政治」「体育」，
勾一样的人看到的东西一模一样。

但人追新闻不是这么追的。你要的不是「政治」——
你想知道的是*某个人这周具体干了什么*、*那场谈判到底动了没有*、
*你真正在意的那件事，相比昨天有什么新进展*。

personal-newsroom 把你会说出口的那句话，变成个性化的基本单位。

## 它做什么

| | |
|---|---|
| **今日** | 每天一份专属简报，每一节围绕**自上一期以来的新进展**来写；另有少量多家媒体都在报、但你没关注的要事，以及往期 |
| **快讯** | 短平快的最新动态，只推过了你意图闸门的 |
| **阅读** | 一个真正的阅读器。正文抽取出来直接在软件里读，不用跳到浏览器 |
| **关注** | 勾一个预置标签，或者自己写一句话。无论哪种，**它怎么帮你找的，你都看得见、改得动** |
| *随时* | 右侧**新闻助手**：询问任何新闻或订阅中的内容，可联网搜索；回答逐条标注来源编号，点开即是原文 |
| *按需* | 从任意新闻打开**深度报道**：读取相关报道全文写成可追问的报道，每个事实都能点回来源 |

**三个不一样的地方：**

1. **不只是标签，是意图。** 预置标签有，一键就能勾。但上限是你自己写的那句话，
   而且系统把它的判断逻辑摊开给你看，不藏在黑箱里。
2. **一切都在你自己机器上。** SQLite 存在你硬盘，你自己的 API key，不用注册，
   没有我们运营的服务器。备份就是拷一个文件夹。
3. **它告诉你什么是*新的*。** 不是每天早上把同一件事重新摘要一遍，
   而是「自从上次跟你说过之后，这件事动了什么」。

## 诚实的能力边界

装之前就该知道。

- **只支持 macOS（Apple 芯片）。** 后台调度、通知、打包都建在 launchd / `SMAppService` 上。
  不支持 Windows 和 Linux，也不打算承诺。
- **睡眠时也更新，需要输一次管理员密码。** 让 Mac 按时自己醒来要装一个系统级的小组件
  （只会调用 `pmset` 预约唤醒）。不装也行，那就只在 Mac 醒着时更新。合盖用电池时 macOS 可能不允许唤醒。
- **社交媒体源是单独的 63 MB 下载。** 微博、B站、知乎、小红书、X 都不提供 RSS，
  要靠 RSSHub 转换，它装好有 370 MB，所以不随应用一起发。在设置里一键启用，
  或者填你自己已有的实例地址。**Telegram 是自己实现的，开箱即用。**
- **Twitter/X 需要你自己提供一份 cookie。** 现在已经没有零配置的免费方式读 X 了。
  你要么提供登录后的 web cookie，要么付费买抓取服务。
- **本地存储 ≠ 完全离线。** 数据在你硬盘上，但发给云端 AI 服务商的内容确实出网了。
  也可以改用本机 Ollama；实际上下文和质量取决于你的本地模型配置。
- **付费墙就是付费墙。** 抓不到正文时阅读器会明说，并提供「在浏览器打开」。
  **不会拿摘要冒充原文。**
- **界面有中文和英文两套**（设置 → 通用，默认跟随系统）。它和 AI 写摘要、快讯用的语言
  是两回事，后者可以全局设置，也可以每个关注单独设置。

## 自己构建

需要 Apple 芯片的 Mac、Node.js 24.15 以上、Go 1.26 以上（编译阅读核心），不需要 Xcode。

```bash
npm ci
```

```bash
npm run package:dir
```

完成后应用在 `release/mac-arm64/所闻.app`。它没有开发者签名，macOS 不会登记它的后台项目，所以没有后台更新，其他功能一样；可用 `npm run worker` 手动更新。
开发时用 `npm run reader:build` 编译阅读核心，`npm run build --workspace=@pnr/desktop` 构建界面，
`npm run start --workspace=@pnr/desktop` 启动。

## 许可证

**AGPL-3.0。** 这是个给「想自己拥有数据的人」用的工具，
所以用了能保证这一点的许可证——**没人能拿走它再做成一个闭源云服务卖回给你**。

同时这也让我们能直接使用 [RSSHub](https://github.com/DIYgod/RSSHub)（同为 AGPL-3.0），
这正是微博、B站这些不用你装 Docker 就能在设置里一键启用的原因。

## 它从哪来

本项目从 `daily-brief` 引出——那是一个双语 AI 新闻门户，每天给所有读者出同一份报纸。
它的管线很好：证据收集、带交叉验证的事件聚类、引用绑定到真实来源的两阶段写作——
但它服务的是一群读者，不是一个人。
personal-newsroom 保留这条管线，把它上面的一切围绕单个读者重建。
